# Uso eficiente do Claude Code (1 página)

- **`/clear`** ao terminar uma parte (depois de commitar). Contexto limpo = menos consumo. Antes, peça o handoff: concluídos / arquivos modificados / próximo passo exato.
- **`/compact`** quando a conversa estiver longa mas ainda precisar do histórico.
- **`/model`**: use o modelo menor (Sonnet) para tarefas repetitivas; reserve o maior para revisão científica e ética.
- **Skills pelo nome**: `/rotina-semanal`, `/lote-narracao`, `/auditoria-tripla-checagem`, `/importar-agendar-textos`, `/aplicar-referencias`, `/video-youtube`, `/post-linkedin`, `/conferencia-19-10`, `/conferencia-26-10`. Cada uma já traz o procedimento; não precisa explicar de novo.
- **Subagentes** (`.claude/agents/`, todos Sonnet): narrador, conferente, varredor, produtor-youtube, produtor-linkedin. Peça "use o subagente varredor" para tarefas repetitivas.
- **Lotes**: peça um lote por vez (ex.: "lote de 50 narrações", "próxima semana da fila do YouTube"), commit ao fim de cada um.
- **Indique os arquivos**: "olhe só `backend/scripts/x.js`" evita varredura do repositório.
- **Sem o Claude**: o Agendador do Windows (`scripts/agendar-tarefas-windows.ps1`) e os crons da Vercel fazem o recorrente; veja `relatorios/ESTADO-GERAL.md` e `relatorios/SE-ALGO-DER-ERRADO.md`.
- **Classificador bloqueou algo permitido (falso positivo)**: não contornar. Saídas: (a) o Dr. Antônio aprova quando o pedido aparecer; (b) roda o comando com `!` (um por linha, sem `cd`); (c) acrescenta a regra em `/permissions`. Regras já liberadas em `.claude/settings.json` (17/10/2026): Read/Glob/Grep/Edit/Write/Skill; `npm run`, `npm test`, `npx playwright`, `node`, `python`, `py`, `ffmpeg`, `ffprobe`, `ls`, `pwd`; git do dia a dia (status, diff, log, add, commit, checkout, switch, branch, fetch, pull, merge, stash, `push origin`, `push -u origin`); `gh pr create/view/list/checks`; `Get/Enable/Disable/Start-ScheduledTask` (hook limita a `DrSM-*`); `chrome-devtools`, PubMed, WebSearch, WebFetch; Vercel só leitura. Pedidas e ainda a gravar pelo Dr. Antônio: `Write(.claude/skills/**)`, `Edit(.claude/skills/**)`. Negadas sempre: `.env`, `client_secret*.json`, merge direto de PR, force-push, `reset --hard`, `clean`, `rm -rf`, `vercel env`, apagar posts, mudar freios.
- **Trava v2 (hook sem falsos positivos) — a aplicar pelo Dr. Antônio.** O `settings.json` e `.claude/hooks/` são protegidos contra edição pelo Claude (regra deny + o próprio hook). A v2 está em `docs/trava-v2/` e testada (34/34 casos em `casos.json`). Para aplicar, digite no Claude Code (usa o Git Bash; um comando por linha, sem `cd`):
  `! node docs/trava-v2/aplicar-trava.js`
  Em PowerShell, o mesmo comando funciona: `node docs/trava-v2/aplicar-trava.js` (a partir da pasta do projeto). O aplicador guarda backup em `backups/trava-*/`, copia o hook novo, acrescenta `Write(.claude/skills/**)`, `Edit(.claude/skills/**)` e `mcp__chrome-devtools` ao allow (sem tocar no deny) e roda 4 testes. Para só conferir sem aplicar: `node docs/trava-v2/testar-trava.js docs/trava-v2/guarda.novo.js docs/trava-v2/casos.json`.
  Regras da v2 (análise por comando, respeitando aspas):
  1. merge de PR: bloqueado só quando o comando COMEÇA com o merge do gh (permitidos: `npm run merge-seguro -- 97`, texto citando o comando em commit/echo);
  2. `.env`/`client_secret`: bloqueado só quando cat, type, Get-Content, grep, sed, cp etc. recebem o arquivo como ARGUMENTO, além de `vercel env pull` (permitidos: `node --env-file=.env x.js`, `cat .env.example`, `sed` com `.env` dentro de um texto entre aspas);
  3. push: bloqueado só quando o DESTINO é main/master (`git push origin main`, `HEAD:main`, `refs/heads/main`) ou `git push` sem destino estando na main; push forçado/delete sempre bloqueado (permitidos: `git push -u origin chore/x`, `gh pr create --base main`).
  Exemplos testados de cada caso (permitido e bloqueado) estão em `docs/trava-v2/casos.json`. Depois de aplicar, commitar o hook/settings novos e acrescentar um teste unitário que rode esses casos.
- **Grafo do código (opcional)**: `graphify explain <id-do-nó>` mostra quem chama e quem é chamado, com arquivo:linha (ver `relatorios/graphify-teste.md`). Prefira `grep -n` direcionado para perguntas simples.
